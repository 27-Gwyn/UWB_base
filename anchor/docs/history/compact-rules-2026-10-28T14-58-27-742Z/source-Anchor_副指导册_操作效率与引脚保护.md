# Anchor 副指导册：操作效率、及时询问与库引脚保护

版本：0.1｜日期：2026-10-28｜适用：Codex 在嘉立创 EDA 专业版绘制本项目 Anchor 原理图。

本册补充主指导册与执行提示词。以下三项来自用户本次明确要求，执行时必须同时遵守：

1. 如无必要，不使用鼠标在前台点击，优先采用可验证的程序接口，减少无效操作与 token 消耗。
2. 遇到影响正确执行的问题，积极、及时询问用户，不靠猜测推进。
3. 不修改嘉立创 EDA 原理图库中的元件引脚定义。

通用 skill 或 API 示例展示某种能力，不代表本任务授权使用该能力。厂家手册可证明某个库定义存在问题，但不构成自行改库的许可。

## 1. 优先使用 API、CLI 或桥接

- 先复用已可用的官方接口、CLI 或 easyeda-api 本机桥接，读取真实工程、文档、器件和引脚数据，再执行绘图、保存与导出。
- 能通过这些接口完成的查询、放置、连线、移动、命名、保存和导出，不改用前台鼠标逐项点击。不要仅为查看对象或确认脚本状态就调起鼠标控制。
- 使用接口批量读取必要对象；缓存未变化的库信息、UUID 和引脚映射。依赖创建、移动后读引脚、连线和保存的步骤仍按顺序执行。
- 保持输出精简，只返回判断当前步骤所需的字段。定位问题时按需展开详情，不反复输出完整文档树、全部 API 手册或无变化的对象清单。
- 出错或超时后，先回读当前对象与已完成记录，查清部分成功的状态；不要盲目重试创建、重复安装、重复启动服务或不断截图。
- 只有必要操作确实缺少可用程序接口，或必须处理实际客户端交互时，才使用前台 GUI。先简要说明原因、目标窗口与最小操作范围；目标不明确或会涉及未知未保存改动时，先询问。
- 若由用户完成一次手动操作更直接，例如加载扩展或登录，及时说明准确步骤，完成后回到程序接口继续。
- 视觉审查仍需真实全页渲染及必要局部查看；优先导出图像后审查。节约 token 不等于跳过逐页审图、网表核对或规则检查。

## 2. 有问题及时询问

先做少量、有针对性的只读排查。仍无法可靠确定下一步时，应主动提出具体问题，不长时间试错，也不为了避免提问而改库、猜引脚或换料。

应及时询问的典型情形：

| 问题 | 需要向用户说明的内容 |
|---|---|
| 库引脚与手册不一致、料号或封装变体不明 | 器件完整型号、库身份、具体引脚差异、手册依据及影响 |
| 缺少正确库器件 | 已查询的候选、缺失内容，以及是否有用户现成的正确器件可用 |
| 接口不可用、错误反复出现、当前状态不明 | 已验证现象、做过的针对性排查和最小需要协助的事项 |
| 多窗口无法确定目标、存在未知未保存修改 | 当前候选工程身份及可能受影响的内容 |
| 资料矛盾、关键天线/电源条件不足或需要改变既定方案 | 冲突位置、对电路的影响和可行的下一步 |
| 发现先前测试可能改动过库定义 | 当前读回值、可取得的基线及受影响范围；不要擅自恢复或覆盖 |

提问尽量一次说清“实际问题—已有证据—为什么影响下一步—需要用户决定什么”，可附少量真实可行的选项。不要只有“失败了，怎么办”，也不要给出未经核实的根因。

等待答复时继续完成与问题无关的模块、资料整理或只读核对；依赖用户答案的部分保持待定。常规可逆排版不必逐项询问，但“不要反复询问是否继续”不能被理解成“遇到实质问题也不问”。

## 3. 元件库引脚定义保持只读

### 3.1 禁止修改的内容

保护范围覆盖系统库、公共库、个人库、项目库、缓存库，以及复制或重命名后的同类符号/器件定义：

- 引脚编号、名称、电气类型及方向。
- 单个引脚在符号内的位置、方向、长度或隐藏属性等定义。
- 引脚的多部件归属、隐藏电源脚和编号对应关系。
- 符号引脚与器件/封装焊盘的映射。

不得通过 GUI 库编辑、库 API、源文件编辑、导入覆盖、库更新或生成脚本改变这些定义。不得复制库器件、创建变体或改名后重定义引脚来绕过限制；本任务不自行新建带自定义引脚定义的库器件。

画布器件实例也不能作为绕过路径：不改实例的 pinNumber，不交换编号或功能，不用修改引脚类型消除规则错误，不通过重新绑定焊盘伪装为正确连接。不要执行 API 文档中修改引脚编号的演示代码。

### 3.2 可以执行的绘图操作

- 只读查询库器件、符号、封装和实例的真实引脚，核对厂家手册。
- 选择已有且经核实的正确库器件，放置、整体移动或整体旋转/镜像其画布实例；不得改变其内部引脚定义。
- 将导线连接到实例的真实引脚端点，添加外部网络标签、端口和电源符号。
- 调整位号、数值等实例显示文字的位置与可见性，保持文字内容真实，不通过普通文字伪造引脚名或编号。
- 按明确的电路依据给真正未使用的实例引脚设置 NC；不得批量 NC 来隐藏缺失连接。

引脚端点不在期望网格时，使用读取到的真实坐标布线；可以调整整器件位置或外部导线，不能单独移动、改号或重画库引脚来凑网格。整体旋转后应重新读取端点坐标，不能把合法实例变换误判为库引脚变更。

### 3.3 库不正确时的处理

停止使用有疑点的器件并保留证据，积极询问用户。可以只读查找同一完整型号、封装和引脚定义均正确的既有库候选；无法确定时不自动换料或改库。等待正确库对象期间，完成无关部分，并将受影响区域明确标记为待核。

后续如用户另行要求处理库定义，应单独明确对象、改动范围与验证方法。当前“绘制原理图”的授权不包含该操作。

## 4. 在执行记录中证明已遵守

绘图开始时记录所用器件的库 UUID、符号/封装身份、修订信息和可取得的引脚定义快照。后续按同一方式回读；若能导出定义，再记录哈希。只有取得完整对应证据，才声称已证明库定义未变化。

最终报告至少分别说明：

- 主要采用的程序接口；是否使用前台鼠标，若使用则说明必要性与范围。
- 提出过的问题、用户答复和仍待定的部分。
- 库与实例引脚定义保护的检查范围、结果和不能取得的证据。
- 实际完成的绘图、保存、导出、视觉审查、规则检查和连接核对。

发现意外定义变化时先停止受影响操作，保存诊断并询问，不隐瞒，也不在没有明确范围的情况下自动回滚库。
