## 三、已确定的硬件与工程范围

- MCU 模组：ESP32-S3-WROOM-1-N16R8，使用模组焊盘编号，不能套裸芯片引脚。
- UWB 芯片：DW3220，双天线 PDoA，用于 AoA；结合 TWR 测距支持单物理基站定位。
- 电源：USB 输入，当前方案为 AMS1117 固定 3.3 V 稳压；实际厂家/完整料号、稳定性、压差、瞬态和热预算需要落实。
- 调试与数据：保留原生 USB、3.3 V UART0、EN/RESET 与 BOOT 操作路径；区分 USB OTG 与 USB Serial/JTAG 对内部 PHY 的使用。
- 原理图覆盖 USB/保护/供电、ESP32-S3 最小系统、DW3220 全部引脚和外围、双天线馈电与匹配、调试及测试点。
- 首版已知高度、基站前方区域的二维实验是讨论建议；不要自创未授权的精度、距离、更新率或三维能力承诺。

以当前用户要求为项目范围。具体引脚、额定值和器件连接以对应完整型号的厂家手册为依据；指导册或草案与手册冲突时，记录并修正受影响的建议，不能盲目照抄。若会改变指定主控、UWB 或稳压路线，给出证据并集中提出变更意见，不静默换料。

## 四、连续执行步骤

### 1. 识别项目与建立可恢复工作区

盘点 anchor 目录和当前 EDA 工程。存在明确属于本任务的工程时读取并保存基线；否则在嘉立创 EDA 专业版创建独立工程，建议名 UWB_Anchor_ESP32S3_DW3220。相同工程名不等于相同工程，应记录真实 UUID。

在 anchor 下按需组织 eda、scripts、design、output 和 .pcba-workflow；保存工作记录。已有无关工程、库、PCB 和 Tag 文件保持原状。操作前识别未保存改动，避免切换工程丢失修改。

### 2. 连接嘉立创 EDA 专业版

优先使用已可用且支持当前版本的官方接入能力，或按 easyeda-api skill 使用本机桥接。先发现已运行服务、验证握手、查询窗口及当前文档，再决定是否需要启动服务；不要重复启动。

能由程序接口完成的工作不改用前台鼠标逐项操作。仅在必要交互确实缺少可用接口时采用最小范围 GUI 操作，并先说明原因；遇到不确定状态及时询问。避免重复完整查询、无变化截图和盲目重试，保持必要的视觉审查与连接核对。

可在 EDA API 执行环境中使用 anchor\tools\01_identify_context.js 读取上下文。这个脚本不是普通 Node.js 程序，也没有创建原理图或运行电气检查的功能。

多个窗口优先通过真实工程和文档信息定位，仅在无法区分时询问。需要启动本地辅助服务时使用 Windows 原生安全命令和隐藏后台窗口。依赖缺失时按真实声明处理，不猜 API、不使用编造的器件 UUID 或枚举值。

若缺少必须由用户在客户端完成的扩展安装、登录或连接操作，明确给出唯一必要操作；等待期间继续本地选型、逐脚表和绘图脚本准备。不能在无法连接 EDA 时声称已经完成原生绘图。

### 3. 核对器件并形成完整连接输入

按指导册逐项核对实际库器件、符号和封装。器件搜索不能默认取第一个结果。记录完整 MPN、厂家、手册修订、libraryUuid/deviceUuid、符号针号和实际封装焊盘。

所有库引脚定义保持只读：不改编号、名称、电气类型、引脚几何或符号到焊盘映射，不改画布实例 pinNumber，不复制或重命名后改库来绕过。库与手册不符时保留证据并及时询问，继续无关模块；不得自行修库或通过改引脚消除规则错误。

建立 library_pin_map.csv、pin_connections.csv、bom_draft.csv 和 sources.md。逐脚连接至少记录 reference、pin、pin_name、net、action 和依据；覆盖所有电源、地、模式脚、内部节点、EPAD、保留脚及未用脚。

GPIO 分配先采用指导册建议并检查资源冲突。N16R8 的 GPIO35/36/37 不分配给外设；启动配置相关脚、USB、UART0 分别核对。对 EN/BOOT、DW3220 的 RSTn、CSn、WAKEUP 和模式脚明确上电默认状态。RSTn 依厂家要求使用开漏拉低或释放，不推挽拉高。

DW3220 外部供电与内部稳压器去耦节点分开，晶体按实际型号与封装核对。AMS1117 按实际厂家确认散热片网络、输出电容稳定性、压差与热预算。USB 输入能力、持续损耗和负载瞬态分别检查。

同系列常规无源件、连接器和支持器件由你基于手册与库证据提出合理草案，并标注来源及待核项，无需逐件询问。没有证据的天线实体、晶体物理映射或关键芯片库不能猜填；保留明确标识的待核功能块，先完成其余页面。

### 4. 创建并逐页绘制原生原理图

以下六个功能页作为起点；在同一原理图下按实际阅读成本调整布局，并记录必要合并或拆分理由，不能由分页自动推断为多块 PCB：

1. 00_OVERVIEW：功能、电源树、接口方向与版本。
2. 01_POWER_USB：USB、保护、AMS1117、输入/输出电容与测点。
3. 02_ESP32S3：模组、电源去耦、EN、BOOT、指示与用户按键。
4. 03_DW3220：全部引脚、供电/去耦、晶体、SPI 与控制信号。
5. 04_RF_ANTENNA：两路 RF、匹配、馈点、阵列坐标及布局要求。
6. 05_DEBUG_TEST：UART、调试接口、测试点和上电检查说明。

读取已放置器件的真实引脚坐标后连线，旋转或移动后重新读取。局部电源、USB 支持、复位、晶体、SPI 支持和匹配网络使用可追踪的真实导线。跨页或真正远距离连接使用经过作用域核对的标签/端口。装饰文字、线条或看似相触的端点不能代替电气连接。

先完成一个代表功能模块并回读和渲染，再继续其他模块。按批次记录新建对象 ID；超时先盘点实际状态，再补缺项，禁止无条件重复 create。不要仅为视觉对齐改值、换脚、变极性或合并网络。

双天线保持正确馈电与参考地关系，注释区分厂家要求、设计目标与待测量值。未知层叠时不编造通用 50 Ω 线宽；约 16.9 mm 不能当作已验证天线相位中心间距。未实现的天线不能用随意图形冒充完成设计。

### 5. 保存、导出、连接核对与视觉修正

每页完成后保存并回读；导出全页真实渲染，在正常阅读比例检查，再放大模组、USB、电源、晶体、RF、连接器与页边界。修正文字压线、位号漂移、裁切、歧义交叉、未吸附端点和看似悬空的局部电路。注释加入后重新渲染检查。

通过当前版本实际支持的路径导出原理图规则检查、BOM 和实际网表。SCH_Drc 的布尔结果与详细错误树分开保存，详细树的顶层长度不等于错误总数；记录实际检查范围。不要把原理图规则检查说成 PCB DRC 或实物性能验证。

将 EDA 实际导出的网络与完整逐脚规范比较，覆盖多部件、隐藏电源脚、散热片、多焊盘、跨页标签、装配变体及 NC。先证明导出/规范化适配器能正确读取这些情况，再声称连接一致。预期网络表不能冒充实际导出数据。不要复用旧 STM32 专用校验器。

每个电气变更记录原连接、新连接、依据与影响；纯排版调整核对前后连接保持。检查出问题先修复，再重复受影响的导出和检查，直至本次可完成范围内没有未解释问题。

### 6. 交付可重新打开的结果

保存实际客户端支持的原生专业版工程或导出包，记录其真实格式与路径。先保存确认再在不丢失改动的条件下重新打开核对；有未知未保存状态时先处理，不能强行关窗验证。导出的文件必须真实存在且内容可读。

交付至少包括：

- 原生工程、使用的库及库版本/UUID记录。
- 全部实际图页 PDF/PNG，覆盖所有页面；若导出为压缩包则核对成员及页数。
- 实际 BOM 和网表、library_pin_map.csv、pin_connections.csv、bom_draft.csv、sources.md。
- 原理图规则检查原始输出、连接比较结果、全页与密集区域的视觉检查记录。
- 可重复执行的必要脚本、对象/文档身份记录、设计决定和剩余问题。
- 前台鼠标操作的必要性与范围、问题询问记录，以及库/实例引脚定义只读保护的证据与局限。
- output\完成情况.md：分别列出已绘制、已保存、已重开、已审图、已运行规则检查、已核对连接，以及未执行项目。

未知条件只阻止依赖它的部分，不阻止无关页面继续推进。若关键未决项尚未关闭，交付明确标为 DRAFT 的真实工程和准确问题清单；不能把占位块算作完成，也不能为了宣称完整而猜测关键 RF 或封装信息。

没有 EDA 连接、实际渲染、规则检查、网表或测量证据时，不得声称相应步骤通过。原理图绘制完成不代表天线、PCB、标定或定位性能已验证。现在开始读取项目输入，简要报告已找到的资料与接入状态，然后连续完成本任务。
