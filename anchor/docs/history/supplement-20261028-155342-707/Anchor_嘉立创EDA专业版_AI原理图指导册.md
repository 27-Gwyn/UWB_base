## 2. 定位原理与硬件分工

DW3220 用两个天线端口取得 PDoA，经过阵列标定得到 AoA；TWR 提供距离。ESP32-S3 负责配置、SPI 访问、中断处理、协议调度、记录与上传，定位的射频时间戳来自 UWB 芯片，不能用 MCU 收到 IRQ 的时间替代。[S1]

双天线的一条基线只提供一个独立方向约束。首版可在已知高度和前方区域内求二维位置；一般三维定位还需要更多独立角度约束。距离参考点、两天线坐标和阵列朝向必须随标定记录保存。

建议首先完成：供电与下载 → SPI 读设备信息 → 测距 → PDoA 原始数据 → 角度标定 → 坐标输出。首轮 UWB 调试建议关闭 Wi-Fi/蓝牙；是否启用无线上传再结合电流、温度和任务调度验证。这是调试顺序建议。

本轮只准备指导文件，未安装扩展、启动桥接或连接用户的 EDA。当前 PATH 查询没有发现 lceda-pro，这不能证明桌面客户端未安装。

官方 CLI 的命令与接口应按实际安装版本查询，不照抄另一版本参数。官方文档提供会话查看、API 文档检索及 JavaScript 执行能力。[S4]

### 3.2 写入前识别上下文

配套 01_identify_context.js 只读取编辑器版本、当前工程、原理图和图页。由已连接的 EDA API 执行环境运行，不能用普通 Node.js 直接运行，因为普通 Node.js 中没有 eda 对象。

记录项目 UUID、原理图 UUID、图页 UUID、客户端版本和库版本。只有定位到本任务的新工程或已获授权编辑的工程后，才开始放置器件。不要为探测 API 复制或删除用户现有工程，也不要随意切换可能含未保存修改的工程。

API 支持并不表示当前客户端一定兼容；调用失败时保留返回内容，查对应版本文档后处理。不能根据一个猜测的接口名继续批量写入。

## 4. 器件库先核对，再放置

嘉立创 EDA 中的符号、封装和器件关联是不同的对象。搜索到相同型号后仍需检查物理映射，不能用库名称或预览图作为正确性的证据。

建立 library_pin_map.csv，字段至少包括：reference、manufacturer、mpn、datasheet_revision、datasheet_pin、symbol_pin、footprint_pad、function、verification、source。

| 对象 | 核对重点 |
|---|---|
| ESP32-S3-WROOM-1-N16R8 | 使用模组焊盘，不使用裸 ESP32-S3 管脚号；检查 EPAD 与存储器占用脚 |
| DW3220 | QFN 对应编号、所有电源和地、内部去耦节点、RF 端口、模式脚及裸露焊盘 |
| AMS1117 | 固定 3.3 V 版本、实际厂家数据手册、引脚与散热片网络、输出电容稳定性 |
| USB 连接器 | 完整料号、引脚排列、外壳焊盘、正反插数据脚及安装尺寸 |
| 晶体 | 频率、CL、ESR、封装与实际焊盘定义；不将逻辑名称当作焊盘号 |
| 天线 | 经过选择或验证的馈点、结构、禁布及相位资料 |

没有最终物理映射的对象可以在草图中保留明确标识的待核功能块，不能将其写成已完成建库或混入最终交付 BOM。

## 5. 图页划分与每页完成条件

同一块 Anchor PCB 的所有图页放在同一原理图下。RF 是否独立做子板尚未决定；不要因为文档分页就默认拆成多块 PCB。

| 图页 | 必画内容 | 完成条件 |
|---|---|---|
| 00_OVERVIEW | 电源树、功能块、接口方向和版本 | 能说明能量与数据从哪里进入、流到哪里 |
| 01_POWER_USB | USB、保护、AMS1117、输入/输出电容、供电测点 | 稳压器稳定性、压差及热预算有依据 |
| 02_ESP32S3 | 模组、电源去耦、EN、BOOT、指示与按键 | 模组完整型号、保留脚、默认状态清楚 |
| 03_DW3220 | 全部引脚、供电/去耦、晶体、SPI 与控制信号 | 每脚有 CONNECT、NC 或按手册特殊处理的记录 |
| 04_RF_ANTENNA | 两路 RF、匹配、天线、阵列坐标与布局说明 | 已区分厂家要求、设计目标和待测参数 |
| 05_DEBUG_TEST | UART、USB用途、测试点及上电验证表 | 能下载、恢复、测电源并观察关键控制信号 |

电源、晶体、复位、按键、USB 支持电路与局部匹配网络用可追踪的原生导线连接。跨页信号使用清晰的网络标签或端口，并核对标签的连接范围；不能用整页孤立标签代替局部电路。[S5]

### 5.1 USB 与 AMS1117 页

若采用 USB-C 受电接口，应画清 CC1/CC2、VBUS、GND、数据线、外壳及 ESD。电源预算要同时满足上游 USB 源能力和稳压器能力；保险丝额定值不能充当 USB 允许取电电流的证据。

AMS1117 暂按用户方案保留，先确认真实厂家和固定输出后缀。以 AMS 厂家手册为参考时，SOT-223 散热片属于输出网络；最终仍以购买料号手册为准。输出电容须按对应稳压器的稳定性要求选择，不能仅凭同容量就换成任意低 ESR 陶瓷电容。[S3]

计算近似线性损耗：P = (VIN − VOUT) × IOUT。5 V 转 3.3 V 时，300 mA 对应约 0.51 W，500 mA 对应约 0.85 W，未计静态损耗。持续负载用于热估算，瞬态负载用于压降和复位风险检查；两者不能互换。

记录 USB 线缆、保护器件和走线造成的输入压降，结合温度与负载检查压差余量。是否更换稳压器属于后续工程决定，不能让绘图 AI 自动换料。

### 5.2 ESP32-S3 页与 GPIO 草案

本项目使用 ESP32-S3-WROOM-1-N16R8，具有 16 MB Flash 和 8 MB Octal PSRAM。模组 GPIO35、36、37 由存储器占用，不能分配给 UWB；GPIO0、3、45、46 属于启动配置相关引脚。完整模组包含 EPAD 共 41 个焊盘，编号应按模组表核验。[S2]

以下是 GPIO 分配建议，尚非已导出并验证的 EDA 网表。U2 为本册建议的模组位号。

| 功能 | 模组信号 | U2 物理焊盘 | 方向/备注 |
|---|---|---|---|
| 3.3 V | 3V3 | 2 | 电源输入 |
| 地 | GND / EPAD | 1、40、41 | 接地；按模组布局要求处理 |
| 使能/复位 | EN | 3 | 上拉、上电时序与复位按钮 |
| 下载按钮 | GPIO0 | 27 | 按下载模式要求处理 |
| USB D− / D+ | GPIO19 / GPIO20 | 13 / 14 | 保留给原生 USB |
| UART0 TX / RX | GPIO43 / GPIO44 | 37 / 36 | 接 3.3 V UART 调试器 |
| UWB SCK | GPIO12 | 20 | MCU → DW3220 |
| UWB MOSI | GPIO11 | 19 | MCU → DW3220 |
| UWB MISO | GPIO13 | 21 | DW3220 → MCU |
| UWB CSn | GPIO10 | 18 | MCU → DW3220，启动默认非选中 |
| UWB IRQ | GPIO9 | 17 | DW3220 → MCU |
| UWB RSTn | GPIO8 | 12 | 开漏拉低或释放 |
| UWB WAKEUP | GPIO7 | 7 | MCU → DW3220 |
| 状态灯 / 用户按键 | GPIO15 / GPIO16 | 8 / 9 | 通过限流或上下拉支持电路 |

固件与原理图必须引用同一份分配表。模组外围应按模组推荐电路绘制，避免重复添加模组已集成的 MCU 晶体和存储器。模组自身的 2.4 GHz 天线禁布区也需要保留。[S2]

原生 USB 可配置 USB Serial/JTAG 或 USB OTG，二者共用内部 PHY。用于 USB 通信不自动意味着能够同时进行内置 USB JTAG 调试。UART0、BOOT 和 EN 应保留可操作的恢复路径。[S7]

### 5.3 DW3220 页

按 DW3220 对应封装逐脚建立连接记录，不能套用单天线器件或 WLCSP 的脚号。外部电源输入与内部稳压器去耦节点必须区分；不能把所有名称含 V 的引脚接到 3.3 V。[S1]

RSTn 按厂家开漏要求处理，MCU 不推挽拉高，也不擅自加 GPIO 上拉。SPI 模式脚、CSn 和 WAKEUP 在 MCU 尚未运行时应有明确默认状态。检查 MCU 与 UWB 部分掉电时的反向供电路径。[S1]

38.4 MHz 参考晶体的完整型号、负载电容、ESR 及封装映射在该页关闭。SPI 初始 2 MHz、运行先以 16 MHz 调试可作暂定目标，最终受芯片状态、SDK 配置和实测信号质量约束。STS、PDoA 模式与帧参数必须采用同一 SDK 的兼容配置，不由绘图 AI 各自猜定。

### 5.4 双天线页

两路 RF 的器件、过孔、参考地及结构差异会影响相位，需要纳入标定。50 Ω 是阻抗要求，线宽/间距要由板厂层叠计算；原理图不能在叠层未知时给出通用线宽。[S1]

图中明确标记天线相位中心、基线方向、坐标原点和前方区域。既有资料中的约 16.9 mm 间距只是 CH9 下的初步目标，不是已验证天线尺寸。馈点距离、器件外壳距离与有效相位中心间距不能混为一谈。

AI 可整理匹配和馈电连接、标注布局约束；天线实体需要实验室既有设计或后续射频验证。S 参数、方向图、互耦、相位偏差和标定表均不能用文字推演冒充实测。

## 6. 每页绘制后的检查闭环

1. 保存并回读原生对象，确认所写内容位于正确图页。
2. 导出全页真实渲染，再放大检查模组、USB、电源、晶体、RF 和连接器区域。
3. 检查文字压线、导线穿符号、引脚端点未吸附、歧义交叉、裁切和局部功能看似悬空的问题。
4. 运行原理图规则检查，记录实际检查范围与全部结果。嘉立创专业版 API 名称为 SCH_Drc，不能据此声称已执行 PCB 的布局布线 DRC。[S6]
5. 导出实际网表及 BOM，按本版完整连接规范逐脚比较。NC 与未导出的单端网络要单独核对，不能仅因网表没有出现就认为已正确标 NC。
6. 每次电气修改都记录旧连接、新连接、理由和受影响文件；纯排版修改应证明连接没有变化。

规则检查的布尔结果和详细错误树分别保存；详细树的顶层长度可能是错误分组数，不应直接写成错误总数。API 返回值也不能替代检查范围和客户端版本记录。[S6]

规范化连接至少记录 reference、pin、net、action。库中散热片多焊盘、多部件符号、隐藏电源脚、网络标签范围与装配变体要有明确映射。现有旧版校验脚本不是本版比较器。

## 7. AI 交付清单与上电验证

| 交付项 | 应能回答的问题 |
|---|---|
| 原生专业版工程及依赖库 | 能否重新打开并编辑？ |
| 完整逐脚连接规范与实际网表 | 每个脚实际接到哪里？ |
| 库映射表与 BOM | 符号、料号和封装是否一致？ |
| 全页 PDF/PNG 及密集区检查记录 | 是否每页都能读懂和追踪？ |
| 原理图规则检查原始结果 | 检查了什么、还剩什么？ |
| 变更记录与未决项 | 哪些是已确认、建议或待测？ |

首次上电按分阶段调试：检查装配与电源短路 → 使用具有限流能力的电源检查空载/复位状态 → 验证 3.3 V 和稳压器温升 → 验证 UART 下载及 EN/BOOT → 验证 USB → 低速 SPI 识别 DW3220 → 逐步开展测距、测角与标定。具体限流值应根据该阶段实际装配和预计负载确定。

用示波器观察模组与 UWB 附近的电源瞬态，用逻辑分析仪观察 SPI/IRQ。可正常下载、读到芯片或通过原理图规则检查，均不等于整板已实现定位性能。

本版主要未决项：AMS1117 真实厂家/封装与热设计；USB 完整连接器料号和供电条件；DW3220 完整订货号及库；晶体；双天线结构与层叠；是否拆 RF 子板；SDK 与帧参数；距离、视场、精度、更新率及验收条件。
