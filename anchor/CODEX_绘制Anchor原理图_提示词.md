## 四、连续执行步骤

只读查询已连接客户端的当前工程、工程树和板子信息，定位 UWB 工程 → Anchor 板子 → 该板子关联的原理图与现有图页。记录工程、板子、原理图及图页的真实 UUID，并核对父子归属，不能只根据当前窗口标题或同名对象判断目标。

读取并保留该原理图的现有内容和已完成部分，在其上继续绘制；不得清空画布后重建。若存在多个同名目标、找不到 Anchor、缺少其关联原理图或无法确定已有内容的处理范围，及时具体询问。目标尚未确定时继续本地资料准备，不新建替代工程、板子或游离原理图。

在 anchor 下按需组织 eda、scripts、design、output 和 .pcba-workflow；保存工作记录。已有无关工程、库、PCB 和 Tag 文件保持原状。操作前识别未保存改动，避免切换工程丢失修改。

### 2. 连接嘉立创 EDA 专业版

优先使用已可用且支持当前版本的官方接入能力，或按 easyeda-api skill 使用本机桥接。先发现已运行服务、验证握手、查询窗口及当前文档，再决定是否需要启动服务；不要重复启动。

能由程序接口完成的工作不改用前台鼠标逐项操作。仅在必要交互确实缺少可用接口时采用最小范围 GUI 操作，并先说明原因；遇到不确定状态及时询问。避免重复完整查询、无变化截图和盲目重试，保持必要的视觉审查与连接核对。

可在 EDA API 执行环境中使用 anchor\tools\01_identify_context.js 读取上下文。这个脚本不是普通 Node.js 程序，也没有创建原理图或运行电气检查的功能。

多个窗口优先通过真实工程和文档信息定位，仅在无法区分时询问。需要启动本地辅助服务时使用 Windows 原生安全命令和隐藏后台窗口。依赖缺失时按真实声明处理，不猜 API、不使用编造的器件 UUID 或枚举值。

### 3. 核对器件并形成完整连接输入

先只读盘点用户先前原理图、当前板子的既有器件与历史 BOM，同类功能优先参考实际使用过且适用于当前设计的元件，记录出处与库身份，不虚构既往使用记录。再按指导册逐项核对实际库器件、符号和封装。器件搜索不能默认取第一个结果。记录完整 MPN、厂家、手册修订、libraryUuid/deviceUuid、符号针号和实际封装焊盘。

所有库引脚定义保持只读：不改编号、名称、电气类型、引脚几何或符号到焊盘映射，不改画布实例 pinNumber，不复制或重命名后改库来绕过。库与手册不符时保留证据并及时询问，继续无关模块；不得自行修库或通过改引脚消除规则错误。

建立 library_pin_map.csv、pin_connections.csv、bom_draft.csv 和 sources.md。逐脚连接至少记录 reference、pin、pin_name、net、action 和依据；覆盖所有电源、地、模式脚、内部节点、EPAD、保留脚及未用脚。

GPIO 分配先采用指导册建议并检查资源冲突。N16R8 的 GPIO35/36/37 不分配给外设；启动配置相关脚、USB、UART0 分别核对。对 EN/BOOT、DW3220 的 RSTn、CSn、WAKEUP 和模式脚明确上电默认状态。RSTn 依厂家要求使用开漏拉低或释放，不推挽拉高。

DW3220 外部供电与内部稳压器去耦节点分开，晶体按实际型号与封装核对。AMS1117 按实际厂家确认散热片网络、输出电容稳定性、压差与热预算。USB 输入能力、持续损耗和负载瞬态分别检查。

同类常规无源件、连接器和支持器件优先采用先前原理图中经核对适用的料号，再基于手册与库证据补齐缺项；来源、复用理由和待核项写入图外器件表，无需逐件询问。缺少历史资料时及时询问来源，不把猜测写成复用事实。没有证据的天线实体、晶体物理映射或关键芯片库不能猜填；在图外问题清单记录缺项并先完成无关部分，不在画布添加文字或图框冒充已完成模块。

### 4. 在现有 Anchor 板子内逐页绘制原理图

先盘点该 Anchor 板子的现有图页和已有有效电路，按功能矩形包络紧凑规整排布，暂不画模块框。相关简单模块可合并，不机械遵循旧版六页分类，不增加纯文字总览页或 Notes 页；面积和页数以可读性及查线成本决定。只调整该板子现有原理图内的必要图页，不创建其他工程或板子。以下内容是功能分组，不是一组必须逐个新建的图页：

1. USB 与电源：接口、保护、AMS1117、输入/输出电容与测点。
2. ESP32-S3：模组、电源去耦、EN、BOOT、指示与用户按键。
3. DW3220：全部引脚、供电/去耦、晶体、SPI 与控制信号。
4. 双天线 RF：两路馈电、匹配与已确定的天线对象。
5. 调试与测试：UART、调试接口和测试点。

系统总览、坐标定义、RF/布局约束、计算、待核项及上电检查说明全部保存为图外文档，不在原理图画布添加说明性文字。保留位号、器件参数、原有引脚名/编号、原生网络标签与必要图签字段。

读取已放置器件的真实引脚坐标后连线，旋转或整体移动后重新读取。逐一压缩所有引脚外接线的无必要长度，使外围电路紧凑，保留可读串并联、反馈和分支关系；不得修改库内引脚的长度或位置。所有网络通过真实导线及附着其上的原生网络标签定义，不使用网络端口、层次端口或以旗标替代该表达。跨页连接必须核对标签作用域及导出网表；普通文字和看似相触的端点不能代替电气连接。

先完成一个代表功能模块并回读和渲染，再继续其他模块。按批次记录新建对象 ID；超时先盘点实际状态，再补缺项，禁止无条件重复 create。不要仅为视觉对齐改值、换脚、变极性或合并网络。

双天线保持正确馈电与参考地关系，厂家要求、设计目标与待测量值在图外文档中分别记录，不在画布添加文字注释。未知层叠时不编造通用 50 Ω 线宽；约 16.9 mm 不能当作已验证天线相位中心间距。未实现的天线不能用随意图形冒充完成设计。

### 5. 保存、导出、连接核对与视觉修正

每页完成后保存并回读；导出全页真实渲染，在正常阅读比例检查，再放大模组、USB、电源、晶体、RF、连接器与页边界。修正文字压线、位号漂移、裁切、歧义交叉、未吸附端点和看似悬空的局部电路。器件、标签或外接线调整后重新渲染检查，并确认没有端口、新增说明性自由文本或默认模块框。

通过当前版本实际支持的路径导出原理图规则检查、BOM 和实际网表。SCH_Drc 的布尔结果与详细错误树分开保存，详细树的顶层长度不等于错误总数；记录实际检查范围。不要把原理图规则检查说成 PCB DRC 或实物性能验证。

将 EDA 实际导出的网络与完整逐脚规范比较，覆盖多部件、隐藏电源脚、散热片、多焊盘、跨页标签、装配变体及 NC。先证明导出/规范化适配器能正确读取这些情况，再声称连接一致。预期网络表不能冒充实际导出数据。不要复用旧 STM32 专用校验器。

每个电气变更记录原连接、新连接、依据与影响；纯排版调整核对前后连接保持。检查出问题先修复，再重复受影响的导出和检查，直至本次可完成范围内没有未解释问题。
