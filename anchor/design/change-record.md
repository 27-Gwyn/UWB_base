## 电气修复

- 实际网表发现 MCU 接地支路碰到 +3V3 竖轨，另一路 C3 导线跨过电容两端，导致电源地合并。已更换受影响的本次新建导线组，地轨分开并使 C3 两端分别为 +3V3/GND。
- 实际网表发现 IRQ 与 SPIPHA 支路端点重合，以及 XTO 与一条去耦地支路端点重合。已将模式脚转折点和晶体线转折点移开，修复后重复完整 204 脚比较无差异。
- 所有修复均仅处理外部导线；未修改库/实例引脚编号、名称、类型或内部几何。
- 删除 28 条同一 WIRE 组内完全同值的冗余 NET 属性，保留每组一个网络名。使用文档化 setDocumentSource 原位更新当前 SCH_PAGE；所有器件、引脚与图页 ID 保留，修改前后实例引脚状态完全一致。网表比较再次通过。
- 输出钽电容根据库符号“+”与焊盘 1 核验，整体转向使正端在上；C2.1=+3V3，C2.2=GND。未交换编号。

## 客户端适配与证据局限

- 系统库导入工程后得到工程内 UUID，已记录 source→local 对应关系，不能直接拿两个 UUID 不同认定器件换料。
- 此客户端属性字号 API 使用英寸尺度，9 会变为源文件 900；已校准为 0.08 等实际字段值并重新渲染。文字属性位置改变不改变电气连接。
- 普通 pin.modify 的 NC 标记未生效，改用文档化异步 NoConnected 提交后，重开核实 31 个 NC。没有调用 PinNumber 等定义修改方法。
- 原生 PDF 导出 API 超时；未重复盲试。画布 API 重开后出现全透明返回，失败图像不得交付。有效阶段渲染单独保留，最终渲染结果以完成情况记录为准。
- EPRU 的末记录可能没有末尾分隔符；适配器已修正并以该实际边界条件验证，避免漏掉最后一个焊盘/引脚属性。

## 用户答复

1. 用户启用扩展，桥接连接后继续；后来连接窗口 ID 改变，重新核对同一工程/板子/原理图/图页归属。
2. 用户无双天线既有设计，同意 RF 页/区域标待核；随后要求所有内容合并为一张图。
3. 用户无已验证晶体，允许在问题不严重时考虑 TXC。因 ESR 冲突未获技术关闭，保留 DNP 候选，不声称可安全起振。
4. 用户导出 DRC 文本，已用于分类原始警告。清理后最终汇总再次请求用户导出，是否取得以完成情况记录为准。
